# agent-playbook

How I build, evaluate and operate an AI agent that a real team uses: instructions treated as code, a learning loop that turns corrections into rules, an evaluation harness with regression diffing, and a monitoring report that ties a bad week to the instruction change that caused it.

It is distilled from building a team-facing analytics agent for a product R&D team, and from using a personal agent daily for about three months. **Everything in this repository is generalized or synthetic. It contains no employer data.**

## What this demonstrates

- **Evaluation-driven development.** A deterministic grading harness (`evalkit`) over a case set, with a `diff` that reports what a change fixed, what it broke and what still fails. A higher pass rate can hide a regression; the tool surfaces it.
- **Instructions as a versioned artifact.** Structure, quality bar for rules, and a template, not a long prompt pasted into a box.
- **A feedback loop that is selective.** Corrections are triaged before they become rules, because a rule file that records everything cannot be followed.
- **Operational thinking.** A weekly monitoring report (`monitor`) with an alert rule and a candid note on its noise.
- **Honest limits.** Each chapter says what the repository does not prove.

## Try it

Python 3.9+, standard library only.

```bash
python3 -m unittest discover -s tests           # 44 tests

python3 -m evalkit run  --cases evals/cases/inventory_assistant.jsonl --responses evals/transcripts/v1.jsonl
python3 -m evalkit diff --cases evals/cases/inventory_assistant.jsonl \
        --before evals/transcripts/v1.jsonl --after evals/transcripts/v2.jsonl

python3 -m monitor report --logs monitoring/sample_logs.jsonl
```

Real output of the `diff`:

```
v1 -> v2
  pass rate 72% -> 92%
  regressed: tr4
  fixed: md1, tr3, ap1, fm3, sr2, nm1
  still_failing: nm4
```

`md1` is a metric-definition failure (a quantity already net of reserved stock is reduced a second time). `tr4` is the regression: an instruction meant to make the agent check the data first made it query data for an out-of-scope question.

## What is synthetic

- The inventory assistant, its SKUs and its glossary are invented.
- `evals/transcripts/v1.jsonl` and `v2.jsonl` are **hand-written** to illustrate a realistic failure and fix. They are not output from a real model. The harness can grade a live agent through `run_cases(cases, callable)`.
- `monitoring/sample_logs.jsonl` is generated by `monitoring/make_sample_logs.py` with a fixed seed and says nothing about any real agent.
